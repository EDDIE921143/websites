# Ediz OS 0.3.21 — reading, questions and spacing

This update follows the 0.3.20 tutorial refresh. It tightens the assistant message bar, groups Assistant and Moshia toolbar controls, separates chapter context from its AI action, and gives the guide a small level-reactive voice mark. The “One step closer” feedback is centered; the course-complete card is shorter.

Capture now offers **Clarify with questions**. The connected assistant asks up to three specific questions about the draft. Ediz can answer, review the rewritten first-person thought, and choose whether to use it before saving. The AI Notes Lab also demonstrates answering a question. The production polish instruction now uses a natural paragraph for short ideas and treats an explicit answer as resolving that particular unknown while retaining other uncertainty.

Full Book’s Contents has an **Audiobook** section at the end. Listen from the beginning or the current chapter to play the book in order with the selected natural voice. A compact bar shows the current chapter, pause/resume, 0.75×–1.5× speed, voice choice, retry and stop. Changing voice restarts the current chapter; leaving the reader stops playback. This uses the connected assistant and sends the requested chapter text to its speech service; provider availability and quota still apply. The original Scrivener source is unchanged.

Validation: JavaScript/API tests and web build passed. An invented captured idea was clarified through the real connected iPhone flow. An invented sample chapter produced a measured natural-voice audio signal on the iPhone. Reading and rehearsal lessons, the AI notes lab, and spoken tutorial controls also passed their physical tests. One multi-test run lost Xcode’s UI gesture authorization during the spoken test; the same test passed in an isolated rerun. These measurements confirm audio output, not how it sounds to a listener in the room. GitHub Actions and signed Release installation are tracked separately.
