# Ediz OS tool research — 3 October 2026

The current release fixes Capture overlays directly: no transcript during recording, a microphone-driven listening visual, full text after Stop. A timestamp-revision regression test prevents a growing recognition hypothesis from being appended twice. These changes are installed and launched on the paired iPhone. The candidate tools below have been researched, not added to the shipped app.

| Candidate | What it helps | Fit and implementation decision |
| --- | --- | --- |
| [Apple SpeechAnalyzer](https://developer.apple.com/videos/play/wwdc2025/277/) | Long thoughts, lectures and conversations, on-device recognition | Strongest next dictation upgrade on iOS 26+. Replace timestamp heuristics with finalized transcript ranges; retain legacy support for older devices. Requires model availability/download handling and real long-recording tests. |
| [WhisperKit / Argmax OSS](https://github.com/argmaxinc/argmax-oss-swift) | Local multilingual transcription and long audio files | Alternative when Apple language/model support is insufficient. Test speed, battery and accuracy on Ediz’s phone. Model downloads can be substantial; MIT SDK and model terms are separate. The OSS and paid Pro capabilities differ. |
| [Gemini Live](https://ai.google.dev/gemini-api/docs/live-api) | Continuous natural voice conversation, interruptions, tool use and transcripts | Best fit with the existing Gemini account. Full duplex is a larger integration than the current text-to-audio quota recovery. Use short-lived tokens, native echo control, interruption cancellation and actual audio-route tests. Keep the existing original natural voice selection. |
| [LiveKit Swift + Agents](https://github.com/livekit/client-sdk-swift) | WebRTC transport, reconnection, voice-session coordination | Strong option for a dedicated voice service. Needs a room server and persistent agent process (cloud or self-hosted), rather than only a short-lived Vercel function. Do not silently introduce that infrastructure. |
| [Silero VAD](https://github.com/snakers4/silero-vad) | Speech-versus-noise detection for interruption handling | Useful benchmark candidate, not speech transcription or echo cancellation. Requires a compatible native inference runtime and 8/16kHz samples. Compare false interruption rate against Apple voice processing before adding it. |
| [DSWaveformImage](https://github.com/dmrschmidt/DSWaveformImage) | Live waveform, circular envelope, audio-file previews and recording history | Lightweight visual candidate for saved voice memos and rehearsal playback. Existing microphone metering already supplies the input for the installed Capture animation. A library does not repair duplicate transcript handling. |
| [AudioKit UI](https://github.com/AudioKit/AudioKitUI) | Music controls and waveform visualizations | Consider selectively for practice tools. Avoid replacing the whole native audio engine just for a small visual. |
| [Rive Apple runtime](https://github.com/rive-app/rive-ios) | Interactive character states, listening/thinking/speaking and guide celebrations | Best when a custom designed animation asset exists. Drive state and intensity from real app events and audio; respect Reduce Motion. Adding a runtime alone does not create a good visual. |
| [Lottie iOS](https://github.com/airbnb/lottie-ios) | Short completion and tutorial animations | Good for fixed celebration sequences, less suitable than Rive or native SwiftUI for a continuously audio-reactive character. Use the small lottie-spm distribution if adopted. |
| [SwiftSpeech](https://github.com/Cay-Zhang/SwiftSpeech) | SwiftUI wrappers around legacy recognition sessions | Useful implementation reference. Still relies on the older recognition API; adopting it alone does not fix long-form window handling. |
| [SnapshotTesting](https://github.com/pointfreeco/swift-snapshot-testing) | Reproducible layout regressions | Strong app-wide development addition: render long lists, large Dynamic Type, small screens, voice results and recorder states. Supplements actual iPhone audio and gesture tests. |

Priority: long-form native recognition and direct Gemini Live session prototype first; reproducible layout checks next; structured reply/search and attachment improvements assessed below. No subscriptions or new paid services were activated.


## App-wide candidates

| Area | Tool | Benefit and limits | Decision |
| --- | --- | --- | --- |
| Assistant replies | [MarkdownUI](https://github.com/gonzalezreal/swift-markdown-ui) | Native formatted headings, lists, tables and code instead of raw Markdown. Doesn’t decide when to show a result or fix incorrect bot answers. | MarkdownUI is now in maintenance mode. Compare its active successor [Textual](https://github.com/gonzalezreal/textual) before adoption; stress-test lengthy lists and narrow screens. |
| Search and context | [GRDB full-text search](https://github.com/groue/GRDB.swift/blob/master/Documentation/FullTextSearch.md) | Ranked SQLite text search, snippets and maintained indexes. FTS is lexical, not semantic AI. | Use as scalable local candidate retrieval before AI ranking; the existing SQLite storage can gain FTS without a full database migration. |
| Meaning-based search | [swift-embeddings](https://github.com/jkrukowski/swift-embeddings) | Local text embeddings to retrieve similar meanings. Requires a compatible model, language checks and storage/index design. | Benchmark on English/German Ediz project queries; keep existing Gemini ranking while evaluating. |
| Image attachments | [Nuke](https://github.com/kean/Nuke) | Image loading, caching, resizing and native SwiftUI integration. Doesn’t provide image understanding. | Useful if large attachment galleries cause memory or scrolling issues; size images before display and before API upload. |
| Photos and document capture | [Apple Vision OCR](https://developer.apple.com/documentation/vision/recognizing-text-in-images) | On-device text recognition for school notes and documents. Does not perform general sheet-music transcription. | Good native feature: OCR plus source image and editable review, then optional Gemini interpretation. |
| Nearby song recognition | [ShazamKit](https://developer.apple.com/shazamkit/) | Identify recorded audio against a music catalog. Different from generating or playing music. | Optional band feature; match on real rehearsal/ambient audio and show catalog results only after successful identification. |
| Rehearsal playback | AVFoundation + the existing catalog preview lookup | Actual recording playback, pitch-preserving speed and loops are native. Apple catalog samples are previews, not full-song playback. | Keep the existing native player; measure loop timing and output routing rather than introducing MIDI approximations. |
| Crash and performance diagnostics | [Sentry Cocoa](https://github.com/getsentry/sentry-cocoa) | Reports crashes and slow operations; needs a backend/account and careful payload configuration. | Keep local diagnostics first. Remote telemetry remains unactivated; never send notes, chats, manuscript, audio or credentials as diagnostic payloads. |
| Visual regression coverage | [SnapshotTesting](https://github.com/pointfreeco/swift-snapshot-testing) + XCUITest | Screens at multiple font sizes and device widths reveal clipping and overlaps earlier. | Strongest general engineering tool: cover longest list, Capture recording, keyboard composer, call results, guide coach and rehearsal/BPM together. |
| Animation design | Rive / Lottie / native SwiftUI | Rive suits event-driven character states; Lottie suits short authored sequences; native SwiftUI suits small transitions and microphone response. | Use actual state to drive animation and keep Reduce Motion support. No arbitrary animated color/result changes. |

These are assessed choices, not a claim that every dependency is installed. The most useful sequence is: improve transcript foundations, prototype continuous Gemini voice, strengthen reply rendering and local retrieval, then add OCR/music capabilities where a real user flow exists. A general-purpose dependency bundle would not teach the assistant, improve its factual context or repair layout by itself.
